## 1. Що таке граф

**Граф** `G = (V, E)` — це множина **вершин** `V` і множина **ребер** `E`, що їх з'єднують.

- **Неорієнтований** граф: ребро `u — v` працює в обидва боки (дружба).
- **Орієнтований** граф: ребро `u → v` має напрям (підписка, залежність).
- **Зважений** граф: кожне ребро має вагу (відстань, ціна, час).
- **Степінь** вершини — кількість ребер, інцидентних їй.
- **Шлях** — послідовність вершин, сусідні з яких з'єднані ребром.
- **Цикл** — шлях, що починається і закінчується в одній вершині.
- **DAG** — орієнтований граф без циклів.

Далі `n = |V|`, `m = |E|`.

## 2. Представлення графа

| Спосіб | Пам'ять | Перевірка ребра `u-v` | Перебір сусідів |
|---|---|---|---|
| Матриця суміжності (`bool[,]`) | `O(n²)` | `O(1)` | `O(n)` |
| Список суміжності (`List<int>[]`) | `O(n + m)` | `O(deg u)` | `O(deg u)` |

Матриця — для малих і щільних графів, список — майже завжди в інших випадках.
Якщо вершини — не числа `0..n-1`, зручно взяти `Dictionary<TKey, List<TKey>>`.

### Приклад 1. Матриця та список суміжності

```csharp
int n = 4; // кількість вершин: 0, 1, 2, 3
// Ребра неорієнтованого графа як кортежі (u, v)
(int U, int V)[] edges = [(0, 1), (0, 2), (1, 2), (2, 3)];

// Матриця n x n: matrix[u, v] == 1, якщо є ребро u-v
var matrix = new int[n, n];
// Список: adj[u] містить усіх сусідів вершини u
var adj = new List<int>[n];
for (int i = 0; i < n; i++) adj[i] = []; // кожен список треба створити окремо

foreach (var (u, v) in edges)
{
    matrix[u, v] = matrix[v, u] = 1; // граф неорієнтований — ставимо обидва
    adj[u].Add(v);
    adj[v].Add(u);
}

Console.WriteLine("Матриця:");
for (int u = 0; u < n; u++)
{
    // Збираємо рядок матриці через пробіл
    Console.WriteLine(string.Join(' ', Enumerable.Range(0, n).Select(v => matrix[u, v])));
}

Console.WriteLine("Список:");
for (int u = 0; u < n; u++)
    Console.WriteLine($"{u}: {string.Join(' ', adj[u])}"); // лише реальні сусіди
```

**Приклад запуску:**

```
Матриця:
0 1 1 0
1 0 1 0
1 1 0 1
0 0 1 0
Список:
0: 1 2
1: 0 2
2: 0 1 3
3: 2
```

## 3. Обхід у ширину (BFS)

BFS обходить граф «хвилями»: спочатку сусіди старту, потім сусіди сусідів.
Використовує **чергу** (`Queue<int>`). Складність — `O(n + m)`.

### Приклад 2. BFS

```csharp
// Граф: 0-1, 0-2, 1-3, 2-4, 3-5
List<int>[] adj = [[1, 2], [0, 3], [0, 4], [1, 5], [2], [3]];
int n = adj.Length;

var visited = new bool[n]; // щоб не відвідати вершину двічі (усі false)
var queue = new Queue<int>();

queue.Enqueue(0);   // стартуємо з вершини 0
visited[0] = true;  // позначаємо ОДРАЗУ при додаванні в чергу

var order = new List<int>();
while (queue.Count > 0)
{
    int u = queue.Dequeue(); // беремо найстарішу вершину
    order.Add(u);
    foreach (int v in adj[u])
    {
        if (!visited[v])       // новий сусід
        {
            visited[v] = true;
            queue.Enqueue(v);  // він буде оброблений у наступній «хвилі»
        }
    }
}
Console.WriteLine($"BFS: {string.Join(' ', order)}");
```

**Приклад запуску:**

```
BFS: 0 1 2 3 4 5
```

## 4. Обхід у глибину (DFS)

DFS іде «вглиб», доки може, а потім повертається назад. Реалізується **рекурсією**
або явним стеком `Stack<int>`. Складність — `O(n + m)`. Корисний для пошуку компонент,
циклів, топологічного сортування.

### Приклад 3. DFS і компоненти зв'язності

```csharp
// Дві компоненти: {0,1,2} та {3,4}
List<int>[] adj = [[1, 2], [0], [0], [4], [3]];
var visited = new bool[adj.Length];

int components = 0;
for (int u = 0; u < adj.Length; u++)
{
    if (!visited[u])  // вершина ще не належить жодній компоненті
    {
        components++;
        var part = new List<int>();
        Dfs(u, part); // DFS «зафарбує» всю компоненту
        Console.WriteLine($"Компонента {components}: {string.Join(' ', part)}");
    }
}
Console.WriteLine($"Усього компонент: {components}");
Console.WriteLine($"Стеком з 0: {string.Join(' ', DfsWithStack(0))}");

// Рекурсивно відвідує всі вершини, досяжні з u
void Dfs(int u, List<int> part)
{
    visited[u] = true;
    part.Add(u);
    foreach (int v in adj[u])
        if (!visited[v]) Dfs(v, part); // заходимо вглиб до невідвіданого сусіда
}

// Той самий обхід без рекурсії: явний стек замість стеку викликів
List<int> DfsWithStack(int start)
{
    var seen = new bool[adj.Length];
    var stack = new Stack<int>();
    var result = new List<int>();
    stack.Push(start);
    while (stack.Count > 0)
    {
        int u = stack.Pop();
        if (seen[u]) continue; // вершину могли покласти в стек кілька разів
        seen[u] = true;
        result.Add(u);
        // Кладемо сусідів у зворотному порядку, щоб першим дістати першого
        for (int i = adj[u].Count - 1; i >= 0; i--)
            if (!seen[adj[u][i]]) stack.Push(adj[u][i]);
    }
    return result;
}
```

**Приклад запуску:**

```
Компонента 1: 0 1 2
Компонента 2: 3 4
Усього компонент: 2
Стеком з 0: 0 1 2
```

## 5. Найкоротший шлях у незваженому графі

Якщо всі ребра «коштують» однаково, BFS **сам** знаходить найкоротші відстані:
вершина вперше потрапляє в чергу саме з мінімальною кількістю ребер.
Масив `parent` дозволяє відновити сам шлях.

### Приклад 4. BFS із відновленням шляху

```csharp
// 0-1, 0-2, 1-3, 2-3, 3-4
List<int>[] adj = [[1, 2], [0, 3], [0, 3], [1, 2, 4], [3]];
int n = adj.Length, start = 0, target = 4;

var dist = Enumerable.Repeat(-1, n).ToArray();   // -1 означає «ще не досягнута»
var parent = Enumerable.Repeat(-1, n).ToArray(); // звідки ми прийшли у вершину
var queue = new Queue<int>();
dist[start] = 0;
queue.Enqueue(start);

while (queue.Count > 0)
{
    int u = queue.Dequeue();
    foreach (int v in adj[u])
    {
        if (dist[v] == -1)
        {
            dist[v] = dist[u] + 1; // на одне ребро далі, ніж u
            parent[v] = u;
            queue.Enqueue(v);
        }
    }
}

// Відновлюємо шлях від target назад до start за parent
var path = new List<int>();
for (int v = target; v != -1; v = parent[v]) path.Add(v);
path.Reverse(); // зібрали задом наперед — розвертаємо

Console.WriteLine($"Відстань: {dist[target]}");
Console.WriteLine($"Шлях: {string.Join(' ', path)}");
```

**Приклад запуску:**

```
Відстань: 3
Шлях: 0 1 3 4
```

## 6. Алгоритм Дейкстри

Для графа з **невід'ємними** вагами. Ідея: щоразу беремо вершину з найменшою
поточною відстанню (через `PriorityQueue<int, int>`) і **релаксуємо** її ребра:
`dist[v] = Math.Min(dist[v], dist[u] + w)`. Складність — `O((n + m) log n)`.

### Приклад 5. Дейкстра

```csharp
int n = 5;
// adj[u] = список пар (сусід, вага)
var adj = new List<(int To, int W)>[n];
for (int i = 0; i < n; i++) adj[i] = [];

AddEdge(0, 1, 4);
AddEdge(0, 2, 1);
AddEdge(2, 1, 2);
AddEdge(1, 3, 1);
AddEdge(2, 3, 5);
AddEdge(3, 4, 3);

var dist = Enumerable.Repeat(int.MaxValue, n).ToArray(); // «нескінченність»
// Мін-купа: елемент — вершина, пріоритет — відстань; зверху найближча вершина.
// PriorityQueue не вміє зменшувати пріоритет, тому дублікати дозволені
// («ліниве видалення»): застарілі записи просто пропускаємо.
var pq = new PriorityQueue<int, int>();
dist[0] = 0;
pq.Enqueue(0, 0);

while (pq.TryDequeue(out int u, out int d))
{
    if (d > dist[u]) continue; // застарілий запис — вже знайшли коротше
    foreach (var (v, w) in adj[u])
    {
        if (dist[u] + w < dist[v]) // релаксація ребра u -> v
        {
            dist[v] = dist[u] + w;
            pq.Enqueue(v, dist[v]);
        }
    }
}

for (int v = 0; v < n; v++)
    Console.WriteLine($"dist[{v}] = {dist[v]}");

void AddEdge(int u, int v, int w)
{
    adj[u].Add((v, w));
    adj[v].Add((u, w)); // неорієнтований граф
}
```

**Приклад запуску:**

```
dist[0] = 0
dist[1] = 3
dist[2] = 1
dist[3] = 4
dist[4] = 7
```

> Зверніть увагу: пряме ребро `0-1` має вагу 4, але шлях `0-2-1` коротший (3).

## 7. Топологічне сортування

Для **DAG**: впорядкувати вершини так, щоб кожне ребро `u → v` йшло зліва направо
(наприклад, порядок виконання задач із залежностями). **Алгоритм Кана**:
кладемо в чергу вершини з вхідним степенем 0, «видаляємо» їх і зменшуємо степені сусідів.
Якщо в результаті не всі вершини — у графі є цикл.

### Приклад 6. Алгоритм Кана

```csharp
string[] names = ["Труси", "Штани", "Пасок", "Шкарпетки", "Взуття"];
int n = names.Length;
var adj = new List<int>[n];
for (int i = 0; i < n; i++) adj[i] = [];
// u -> v означає «u треба вдягнути раніше за v»
(int U, int V)[] edges = [(0, 1), (1, 2), (1, 4), (3, 4)];

var indeg = new int[n]; // кількість вхідних ребер
foreach (var (u, v) in edges)
{
    adj[u].Add(v);
    indeg[v]++;
}

var queue = new Queue<int>();
for (int u = 0; u < n; u++)
    if (indeg[u] == 0) queue.Enqueue(u); // ні від чого не залежить — можна одразу

var order = new List<int>();
while (queue.Count > 0)
{
    int u = queue.Dequeue();
    order.Add(u);
    foreach (int v in adj[u])
        if (--indeg[v] == 0) queue.Enqueue(v); // усі залежності v виконано
}

if (order.Count != n)
{
    Console.WriteLine("Є цикл — топологічний порядок неможливий");
    return;
}
foreach (int u in order) Console.WriteLine(names[u]);
```

**Приклад запуску:**

```
Труси
Шкарпетки
Штани
Пасок
Взуття
```

## 8. Підсумок

| Задача | Алгоритм | Складність |
|---|---|---|
| Обхід, досяжність | BFS / DFS | `O(n + m)` |
| Компоненти зв'язності | DFS | `O(n + m)` |
| Найкоротший шлях без ваг | BFS | `O(n + m)` |
| Найкоротший шлях, ваги ≥ 0 | Дейкстра | `O((n + m) log n)` |
| Порядок залежностей у DAG | Топосорт (Кан) | `O(n + m)` |

- Список суміжності — стандартний вибір; матриця — для щільних малих графів.
- BFS = `Queue<int>`, DFS = рекурсія/`Stack<int>`.
- Дейкстра **не працює** з від'ємними вагами.

## 9. Питання для самоперевірки

1. Коли матриця суміжності вигідніша за список суміжності?
2. Чому BFS знаходить найкоротший шлях у незваженому графі, а DFS — ні?
3. Навіщо в Дейкстрі перевірка `if (d > dist[u]) continue;`?
4. Що станеться з алгоритмом Дейкстри, якщо в графі є ребро з від'ємною вагою?
5. Як за допомогою алгоритму Кана виявити цикл в орієнтованому графі?
