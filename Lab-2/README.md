# Лабораторна робота 2 — 1 випадкове завдання з 5, 30 хвилин, 5 балів

> **C# / .NET 10.** [Налаштування та запуск](../LABS.md).

На початку роботи викладач випадково визначає для кожного студента **одне
завдання з п'яти**. На виконання призначеного завдання відводиться **30 хвилин**.
Максимальна оцінка — **5 балів**. Завдання мають помірну складність і спираються
на базові операції стандартних колекцій.

| № | Завдання | Обов'язкова колекція |
|---|---|---|
| 1 | Щасливе число | `HashSet<int>` |
| 2 | Додати одиницю до великого числа | `List<int>` |

| 4 | Залишити не більше двох повторів | `List<int>` |
| 5 | Порядок вибування учасників | `Queue<int>` |

Використовуйте стандартні колекції .NET, зазначені у своєму завданні.
Скопіюйте відповідний шаблон **`Program.cs`** у консольний проєкт і замініть
`throw new NotImplementedException()` власною реалізацією.
Кожен шаблон компілюється окремо; до реалізації методу запуск зупиняється
на заглушці. Демонстраційні виклики вже підготовлено, а очікуваний вивід
наведено для завершеного алгоритму. Готових реалізацій у матеріалі немає.

Вхідні дані відповідають умовам завдання; перевірку некоректних аргументів
реалізовувати не потрібно. Передавання `null` не передбачене.

## Завдання 1. Щасливе число — `HashSet<int>`

поверніть `true`. Якщо значення повториться і процес потрапить у цикл,
поверніть `false`.

- `1 <= number <= 1000000`.
- Використайте `HashSet<int>` для збереження вже перевірених чисел.
- Для `number == 1` результат одразу дорівнює `true`.
- **Складність:** O(s) часу та O(s) додаткової пам'яті, де s — кількість

## Завдання 2. Додати одиницю до великого числа — `List<int>`

Невід'ємне ціле число задано списком цифр **від старшої до молодшої**.
Збільште число на `1`, змінивши **той самий список**.

- Список містить від 1 до 10 000 цифр зі значеннями `0–9`.
- Початкових нулів немає, крім окремого числа `[0]`.
- Якщо потрібен додатковий розряд, збільште довжину списку.
  Наприклад, `[9, 9]` перетворюється на `[1, 0, 0]`.
- Не створюйте додаткових колекцій. Заборонено використовувати `BigInteger`
  або перетворювати все число на `int`, `long` чи інший числовий тип.
- **Складність:** O(n) часу в найгіршому випадку, де n — кількість цифр.

## Завдання 3. Розворот фрагментів у дужках — `Stack<char>`

Дано рядок із фрагментами у квадратних дужках. Розверніть символи **всередині
кожної пари дужок**, а самі дужки приберіть. Символи поза дужками збережіть
у початковому порядку.

- Рядок містить від 0 до 10 000 символів: малі латинські літери `a–z`
  та квадратні дужки `[` і `]`.
- Дужки правильно розставлені; **вкладених дужок немає**.
- Порожні фрагменти `[]` дозволені. Якщо дужок немає, поверніть початковий рядок.
- Використайте `Stack<char>` для розвороту фрагментів. Для побудови результату
  дозволено `StringBuilder`. Готові методи `Reverse` не використовуйте.
- **Складність:** O(n) часу та O(n) додаткової пам'яті.

### Приклади з поясненням

| Вхідний рядок | Результат | Пояснення |
|---|---|---|
| `"ab[cd]ef[ghi]"` | `"abdcefihg"` | Фрагменти `cd` і `ghi` стають `dc` та `ihg`; частини `ab` і `ef` не змінюються |
| `"[ab][cd]"` | `"badc"` | Кожен фрагмент розвертається окремо: `ab → ba`, `cd → dc` |
| `"a[]b"` | `"ab"` | Порожній фрагмент не додає символів; дужки прибираємо |

## Завдання 4. Залишити не більше двох повторів — `List<int>`

Дано список цілих чисел, **відсортований за неспаданням**. Поверніть новий
список, у якому кожне значення зустрічається не більше двох разів.
Збережіть початковий порядок чисел.

- Вхідний список містить від 0 до 10 000 елементів; дозволені від'ємні числа.
- Якщо значення зустрічається один або два рази, збережіть усі його входження.
  Якщо більше — залиште рівно два.
- Вхідний список не змінюйте. Результат формуйте у новому `List<int>`.
- Обробіть список одним проходом. Не використовуйте LINQ, сортування
  чи додаткові множини та словники.
- **Складність:** O(n) часу та O(n) пам'яті для результату.

### Приклади з поясненням

| Вхідний список | Результат | Пояснення |
|---|---|---|
| `[1, 1, 1, 2, 2, 3]` | `[1, 1, 2, 2, 3]` | З трьох одиниць залишаємо дві; двійки та трійку зберігаємо |
| `[4, 4, 4, 4]` | `[4, 4]` | Для значення `4` залишаємо лише два входження |

## Завдання 5. Порядок вибування учасників — `Queue<int>`

У черзі стоять учасники з номерами від `1` до `n`. Рахуйте їх по колу:
кожен **k-й учасник вибуває**, а відлік знову починається з `1` для наступного
учасника. Поверніть порядок вибування як `List<int>`.

- `1 <= n <= 1000`, `1 <= k <= 100`.
- Перший відлік починається з учасника `1`, який отримує номер відліку `1`.
- Учасників, які ще не вибули, зберігайте в `Queue<int>`. Для руху по колу
  використовуйте `Dequeue` та `Enqueue`.
- Продовжуйте до порожньої черги. Останнього учасника також додайте до
  результату: список має містити всі n номерів рівно один раз.
- При `k == 1` учасники вибувають у початковому порядку.
  Значення k може перевищувати кількість учасників, які залишилися.
- `List<int>` використовуйте лише для накопичення відповіді.
- **Складність:** не гірше O(n · k) часу та O(n) додаткової пам'яті.

### Приклади з поясненням

| Вхідні дані | Результат | Пояснення |
|---|---|---|
| `n = 5`, `k = 2` | `[2, 4, 1, 5, 3]` | Першими вибувають `2` і `4`, потім відлік переходить через кінець черги. Останнім залишається `3` |
| `n = 4`, `k = 1` | `[1, 2, 3, 4]` | Кожен перший учасник одразу вибуває, тому порядок не змінюється |
| `n = 1`, `k = 5` | `[1]` | Відлік кілька разів проходить через єдиного учасника; результат містить його номер один раз |
